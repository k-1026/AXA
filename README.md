# 메디대구 (MediDaegu)

> **대구 지역 의료기관과 외국인 환자를 연결하는 AI 기반 의료관광·환자 유치 플랫폼**
> 외국인 환자는 자기 언어로 병원을 찾고, 상담 예약부터 방문 후 관리까지 한 곳에서 이용합니다. 입점 병원은 대시보드로 유치 현황과 환자 반응을 확인합니다.

AX Native Bootcamp Local 모듈 · **AXA (데이터 2팀)** · 트랙 AX 데이터·서비스 · 지역 대구

---

## 1. 방향 (2026-11-10 기준)

| 항목 | 내용 |
|---|---|
| 정체성 | AI 기반 의료관광·환자 유치 플랫폼 |
| AXA의 역할 | 메디대구를 운영하며 외국인 환자와 대구 입점 병원을 연결하고 유치 과정을 지원 |
| 유치업 형태 | **직접 유치사업자 등록** 또는 **등록 유치업체와 제휴** — 두 경로 모두 검토 중 |
| 전제 | 서비스는 "등록 유치사업자" **가정**으로 설계·시연합니다. 등록해도 남는 규칙(국내 거주 외국인 유치 금지, 의료 판단 금지, 수수료 상한, 민감정보 별도 동의)은 화면에서 지킵니다 |
| 규제 검토 | 규제샌드박스 적용 가능성(신속확인 우선)과 유치 요건을 함께 검토 |

## 2. 핵심 기능

| 기능 | 내용 | 쓰는 사람 |
|---|---|---|
| **AI 챗봇** | 다국어로 병원 정보·이용 절차를 안내하고 상담 예약으로 연결 (병원 탐색·추천, 가격, 절차 Q&A) | 환자 |
| **상담 예약** | 희망 병원·일정·언어·문의 내용을 입력해 상담 신청 → 병원이 확인·확정 | 환자 → 병원 |
| **사후관리** | 방문 후 병원과 채팅, AI가 대화 요약·주요 키워드를 정리해 병원의 후속 대응·개선에 활용 | 환자 ↔ 병원 |
| **회원가입 구분** | 외국인 환자 / 입점 병원의 가입 절차·이용 권한 구분 | 공통 |
| **입점 병원 대시보드** | 문의·예약 현황, 언어별 수요, 관심 진료과목, 사후관리 문의 시각화 | 병원 |
| **마이페이지** | 상담 예약 내역·진행 상태·사후관리 대화 확인 | 환자 |

- 함께 제공: 병원 찾기(지도·필터), 병원 상세(공공데이터 진료시간·출처·확인일), 가격 가이드(공공 비급여 기준 지역 가격 범위), 5개 언어(한·영·베트남어·중국어 간체·번체)
- 하지 않는 것: 진단·시술 효과·부작용 판단, 국내 거주 외국인 유치, 병원 대신 예약 확정, 이벤트가·후기·순위

## 3. 누구를 위한 서비스인가

| | 미용·외래 (피부·성형·안과) | 치료·검진 (내과·검진·중증) |
|---|---|---|
| **단기 방문 (해외 거주)** | **1순위** — 대만 등 단기 방문객. 챗봇 → 상담 예약 → 사후관리 | 2단계 |
| **국내 거주 (외국인등록)** | 정보 열람만 | 정보 열람만 |

- 돈을 내는 쪽: **입점 병원 (등록 외국인환자 유치의료기관)**

## 4. 수익 모델

| 단계 | 병원이 내는 것 |
|---|---|
| **초기** | 입점 무료 + **건당 중개수수료** |
| **규모가 커진 뒤** | **월 입점료** + 건당 중개수수료 |

- 중개수수료는 고시 상한 안에서만: 진료비의 의원 30%·병원 20%·상급종합병원 15% 이하
- 월 입점료를 함께 받을 때 상한 계산에 합쳐지는지는 **미확인** → 확장 전에 복지부·진흥원 질의로 확인
- 상세: [valuechain/step0_대상정의.md](valuechain/step0_대상정의.md), [research/company/병원과금-비교.md](research/company/병원과금-비교.md)

## 6. 산업 안에서의 위치

- 산업: **의료관광(외국인환자 유치) 산업의 "유치·중개" 층** — 의료 서비스·관광·헬스케어 플랫폼이 겹치는 자리
- 산업 7단계(수요 → 정보·비교 → 상담·유치 → 비자·이동 → 진료·체류 → 정산 → 사후) 중 **정보·비교와 상담·유치가 핵심**, 사후에 한 발
- 우선 기회: **공공데이터 진료시간·가격 + 출처·확인일** (진료시간 채움 26.1% → 빈칸 채우기가 먼저)
- 분석 전체: [valuechain/](valuechain/README.md) (STEP 0~5), 기업 원페이지: [research/company/](research/company/)

## 7. 저장소 구조

```
apps/
├── web-platform/     환자용 웹 (React + TS, Vite) — 챗봇·병원 찾기·상담 예약·마이페이지·사후관리
└── web-hospital/     입점 병원 대시보드
backend/              FastAPI — 인증·병원·예약(booking)·병원 계정(tenant)·사후관리
ai/
├── llm/              LLM 클라이언트 (모든 LLM 호출은 여기로만), safety
├── agent/            챗봇 오케스트레이터·도구·평가
└── chatbot/          문서 검색(RAG)
data/                 raw → interim → processed, etl/ (심평원·메디컬코리아·수성구 데이터)
packages/shared-types FastAPI OpenAPI → TS 타입
research/             리서치 노트 (의료관광·기술·company)
valuechain/           산업 구조·밸류체인 분석
subject/  docs/       기획(plan.md)·규칙(compliance.md)·백엔드 문서
발표/                  진행 발표 자료
```

### 브랜치

| 브랜치 | 용도 |
|---|---|
| `main` | 합쳐진 결과 |
| `frontend`, `frontend-*` | 환자 웹 |
| `backend`, `backend-A-*`, `backend-B-*` | 백엔드 (A: 환자·인증, B: 병원·예약) |
| `ai` | 챗봇·에이전트 |
| `research-data` | 리서치·데이터 |
| `presentation*` | 발표 자료 |

## 8. 실행

```bash
# 환자 웹
cd apps/web-platform
npm install
npm run dev        # http://localhost:5173
```

- 백엔드·AI: Python 3.12 + uv (`pyproject.toml`, `uv.lock`). 실행 방법은 [backend/AGENTS.md](backend/AGENTS.md)와 각 폴더 문서 참고
- 환경변수: `.env.example`을 복사해 `.env` 작성 (**`.env`는 커밋하지 않음**)
- 시연은 **가상 병원·가상 환자 데이터만** 사용

## 11. 협업 규칙

- 작업 전 pull, 의미 있는 변경 1개 단위로 커밋하고 바로 push
- 각자 맡은 폴더·파일에서 작업, 공용 파일(`README.md`, `CLAUDE.md`, `subject/subject.md`)은 팀에 알린 뒤 수정
- 리서치 노트는 맨 아래에 출처(URL · 등급 · 기준 시점 · 확인일). 출처 없는 숫자는 쓰지 않고 "미확인"
- `.env`·API 키·실제 환자 정보는 커밋 금지
