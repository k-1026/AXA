## 0. 단계

| 단계 | 기간 | 할 수 있는 것 |
|---|---|---|
| ① 등록 전 시연 | 지금 ~ 등록 | 화면·흐름 시연만. **가상 데이터**, 공개 URL에서는 실제 제출 막음. 실제 병원 이름은 써도 되지만 **가짜 제휴·가짜 가격을 붙이지 않음** |
| ② 등록·제휴 후 | 유치사업자 등록(자본금·보증보험 각 1억 원 이상, 국내 사무소) 뒤 | 상담 예약 요청 전달, 조건 맞춤 제안, 상한 안의 수수료 |
| ③ 비대면진료 시행 후 | 2027-05-27 (해외진출법 제16조의2) 이후 | 사후관리 채팅을 입점 유치의료기관의 외국인환자 비대면진료 **도구**로 확장 (지금은 설계만) |

- 이 문서의 규칙은 **② 기준으로 만들고, ①에서도 화면에서 지키는 모습**을 보여 준다 (방향성 검토 "등록해도 안 풀리는 것")

## 1. 한다 / 하지 않는다

| 한다 | 하지 않는다 |
|---|---|
| 공공데이터 기반 병원·진료시간·공공 가격 열람 (출처·확인일 표시) | 이벤트 할인가·할인율 노출, 외부 사이트 수집 가격 |
| 병원 연락처·홈페이지·지도 링크 | 초청장 발급, 통역 동행, 픽업 |
| 공식 등록·인증 사실 표시 | 순위, "최고"·"최저가", 실력·결과 비교, 후기·평판 인용, 전후 사진 |
| 환자가 고른 병원 1곳에 상담 예약 **요청서** 전달 (②). 확정·진료계약 당사자는 병원 | 환자 대신 제출, 확정됐다고 말하기 |
| 조건(언어·요일·희망 날짜·지역)에 맞는 등록 병원 **조건 맞춤 제안** 최대 3곳 + 이유 + 수수료 관계 고지 (②) | 국내 거주 외국인·미등록 병원 제안·연결 |
| 유치 수수료: **방문 완료·완납 건 진료비 × 지정 %**, 월 정산. 지정 % ≤ 종별 상한 (②) | 정액 건당 금액, 상한 초과 요구 (해외진출법 제9조) |
| 구독(대시보드 이용료): 병원이 수수료 대신 고를 수 있음 (초기엔 수수료만, 나중에 선택 추가) | 구독료에 환자 연결 대가를 넣기 |
| 일반 광고주(화장품·관광 등 비의료) 배너, "광고" 표시 구역에만 | **의료기관 광고** 받기, 건강정보로 광고 타깃팅 |
| 사후관리: 방문 마친 예약의 **비의료 문의**(일정·비용·서류·숙박) 채팅, "진료 상담 아님" 고지 | ③ 전 증상·치료 상담, 시술 후 의료 안내 메시지 |
| 원문 그대로 번역 (원문·번역문 병기) | 번역에 요약·의역·추천 덧붙이기 |

## 2. 코드에서 지킬 규칙

### 2-1. 노출·입점

| 규칙 | 적용 위치 |
|---|---|
| 목록 정렬은 거리·가나다순만. **요금제(수수료·구독)·광고 여부·"온라인 요청 가능"은 목록·챗봇 제안 순서에 반영 X** | `backend/modules/hospital`, `ai/agent/tools`, `web-platform/hospital·map` |
| **입점은 유치의료기관으로 등록된 병원만** (진료과목별 전문의·의료배상책임보험 요건, 해외진출법 제6조). 요청 기능도 등록 병원만 | `backend/modules/tenant` |
| **상담·예약 버튼, 요청서 제출, 조건 맞춤 제안은 등록 병원(`is_registered_facility`)만**. 유치사업자가 미등록 의료기관에 진료계약을 소개·알선하면 등록 취소 사유 (해외진출법 제24조 제1항 제3호). 서버에서 막고 화면에서도 미등록 병원엔 버튼을 보이지 않음 | `backend/modules/hospital·booking`, `web-platform/hospital·reserve` |
| 병원 목록·지도·상세 **열람**은 전체 병원 + 등록 여부 표시·필터 (**잠정**, 3절 5번 회신에 따라 "등록 병원만 노출"로 바꿀 수 있게 서버 필터로) | `backend/modules/hospital` |
| 병원 상세에 전화·이메일 등 다른 접수 경로 항상 표시 (특정 앱 단독 접수 X, 의료법 제15조) | `web-platform/hospital` |
| 가격은 병원 이름 없이 **공공 자료 범위 안 위치**만. 기관 5곳 미만 항목은 숨김 (팀 기준값) | `backend/modules/price`, `web-platform/price-info` |
| 만족도는 병원 내부용. 환자 화면에 후기·만족도 공개 X (의료법 제56조 제2항 제2호 유형) | `web-hospital/analytics`, `web-platform` |
| 병원 대표사진·외부 수집 가격은 정식 공개 전 병원 동의 사진·공공 자료로 교체 | `web-platform` |

### 2-2. 이용 대상

| 규칙 | 적용 위치 |
|---|---|
| **국내 거주 외국인은 정보 열람만**, 상담 예약·조건 맞춤 제안 X (의료법 제27조 제3항 제2호, 시행규칙 제19조의2) | `backend/modules/auth·booking`, `ai/agent` |
| 판단: 회원가입 때 거주국 + 3문항 — ① 외국인등록(G-1 제외) ② 국내거소신고 외국국적동포 ③ 건강보험 가입자·피부양자. 하나라도 "예"면 국내 거주로 봄. **요청서 제출 때 한 번 더 확인** | `web-platform/login·booking-request`, `backend/modules/patient` |
| 챗봇은 로그인 필요. 체류 형태를 추측해 기록하지 않음 | `web-platform/chatbot`, `ai/agent/tools` |

### 2-3. 예약·정산

| 규칙 | 적용 위치 |
|---|---|
| 예약 상태 기본값 = `pending`. `confirmed`는 병원 직원 계정만. 환자 화면 "확정"은 직원이 확정한 뒤만 | `backend/modules/booking`, `web-hospital/calendar` |
| 답장은 직원 승인 후 발송. 자동 발송은 접수 확인 메시지만. 사후관리 AI 요약·초안도 같은 원칙 | `ai/agent/workflows`, `web-hospital/agent-settings` |
| 정산: 병원이 방문 완료 + 진료비 입력 → 환자 확인(선택) → 월말 완납 건 합계 × 지정 % → 정산서 → 병원 확인. 통역·숙박 등 비의료서비스는 진료비에서 뺌 (고시 제2조) | `backend/modules/booking·subscription` |
| 병원에서 받는 결제 정보는 **예약번호·방문일·진료비(완납 여부)만**. 진료 항목·진단명 X | `backend/modules/booking` |
| 유치 실적(방문 완료) 기록은 두 요금제 모두 남김 | `backend/modules/booking` |
| 구독 요금 기준 = 기능·좌석·AI 사용량 (환자 수와 무관). 그 달 구독료가 "경유 진료비 합계 × 상한"보다 크면 차액을 돌려주거나 다음 달에서 뺌 → 구독 병원도 방문 완료·진료비 합계는 입력 (**잠정**, 출시 전 복지부 질의) | `backend/modules/subscription` |

### 2-4. 개인정보

| 규칙 | 적용 위치 |
|---|---|
| 요청서 동의는 **각각 따로** 4개: 수집·이용 / **병원 제공** / 건강정보(선택, 제23조) / 국외이전(해외 LLM, 제28조의8) | `web-platform/booking-request`, `backend/modules/consent` |
| 법적 구조 (**잠정**, 질의 대상): 요청서를 병원에 보내는 것 = **제3자 제공**(환자 동의, 제17조). 병원 대시보드 안의 AI 요약·번역 = **병원이 맡긴 위탁**(문서 계약, 제26조) | `docs/backend-plan.md`, 처리방침 |
| 챗봇 첫 입력 전 건강정보·국외이전 동의 + AI 사전 고지 (인공지능기본법 제31조) | `web-platform/chatbot` |
| 챗봇 대화는 개인정보를 가린 글만 저장, 30일 후 삭제·삭제 버튼·탈퇴 즉시 삭제. 요청서 초안의 건강정보·문의 내용은 서버에 저장 X (결정 16) | `backend/modules/chatbot`, `ai/agent/service.py` |
| 챗봇 답에 "AI 생성" 표시, 응급 고정 문구는 제외 | `web-platform/chatbot` |
| LLM 호출 전 개인정보 마스킹. 무료 LLM에는 가상 데이터만 | `ai/llm/safety.py` |
| 병원 데이터는 해당 병원(tenant)만 조회·집계, 다른 병원 숫자는 어떤 형태로도 X. 소표본은 **서버에서** 숨김 | `backend/modules/tenant`, `web-hospital/analytics` |
| 광고는 언어·국가로만 고름 (관심 시술·진료과로 타깃팅 X). 광고 쿠키를 쓰면 가입 동의에 광고 항목 따로 | `apps/web-platform` |

### 2-5. AI 답의 범위

| 규칙 | 적용 위치 |
|---|---|
| 증상·시술 판단(진단·효과·부작용·약)은 거절 → 병원 상담으로 (의료법 제27조 제1항). 진료과는 일반 안내만 ("보통 피부과에서 다룹니다") | `ai/llm/safety.py`, `ai/agent/prompts`, `ai/agent/eval` |
| 조건 맞춤 제안은 1절 조건으로만 (`docs/agent-spec.md`). 용어는 **"추천"이 아니라 "조건 맞춤 제안"** | `ai/agent/tools/chat_tools.py`, 화면 문구 |
| 비자는 객관적 공개 정보만 + 메디컬코리아·병원 국제진료센터로 연결 | `ai/agent/prompts` |
| **비대면진료 중개매체 규정 (2026-12-24 시행, 의료법 제34조의8·9)**: 챗봇·채팅이 진료 상담으로 넘어가지 않게 설계로 보장. 시행 뒤 조건 맞춤 제안의 허용 범위 다시 확인 | `ai/agent`, `web-platform/aftercare` |

### 2-6. 시연 (단계 ①)

| 규칙 | 적용 위치 |
|---|---|
| 공개 URL에서는 요청서 실제 제출을 막고 "시연용, 실제 예약 안 됨" 배너. "유치사업자"라고 자칭하지 않음 (해외진출법 제6·23·28조). 등록 병원도 **유치사업자가 아닌 자**의 소개를 받으면 등록 취소 사유라(제24조 제1항 제4호) 등록 전에 실제 병원으로 요청이 가면 **병원 쪽도 위험** | `backend` 설정값, `web-platform` |
| 실제 병원에 **예시 예약 가능 시간**을 붙이지 않음 (가짜 제휴처럼 보임). 예시 일정은 가상 병원(`is_demo`)에만, 실제 병원은 "예약 가능 시간 정보 없음" | `web-platform/reserve` |
| 시연 데이터는 가상 환자·가상 요청만 | `data/processed/demo/` |
