# 챗봇: 국내 거주자 "예약 안 됨" 안내가 늦게 나오는 문제 (2026-11-26)

## 현상
가입 때 거주국을 **대한민국**으로 고른 계정은 상담 요청(예약)을 할 수 없다 (국내 거주 = 유치 대상 아님).
그런데 챗봇은 병원을 고르고 "예약해 줘"라고 한 **3번째 턴에야** 안 된다고 말한다. 그 전에는 오히려 예약을 도와주겠다고 한다.

## 재현 (nemotron, 계정 residency=resident)
| 턴 | 사용자 | 챗봇 | 도구 |
|---|---|---|---|
| 1 | 수성구 여드름 흉터 피부과 찾아줘 | 병원 2곳 + **"상담 요청을 도와드릴까요?"** | suggest_department, search_hospitals |
| 2 | 추천해 줘. 12월 4일 10시 예약하고 싶어 | "추천은 단기 방문자만" + 목록 + **"상담 요청 초안을 만들어 드릴게요"** | recommend_hospitals → not_available, search_hospitals |
| 3 | 첫 번째 병원으로 예약해 줘 | **여기서 처음** "상담 요청은 단기 방문자만 가능, 병원에 직접 연락" + 전화번호 | prepare_booking_request → not_available |

## 확인한 것
- 거주국 → 체류 형태 변환은 정상: `backend/src/modules/patient/schemas.py` `ResidencyIn.residency()` — 거주국이 `KR`이거나 3문항 중 하나라도 "예"면 `resident`
- 챗봇까지 전달도 정상: `backend/src/modules/chatbot/service.py:54` → `PatientInfo.residency` → 시스템 프롬프트 `residency=resident`
- **원인: 시스템 프롬프트에 "resident면 처음부터 예약이 안 된다고 말하라"는 규칙이 없다.** (`ai/agent/prompts/orchestrator.py`)
  - 거절은 도구(`prepare_booking_request`, `recommend_hospitals`)가 `not_available`을 돌려줄 때만 일어난다
  - 그 도구는 사용자가 병원을 고른 뒤에야 불리므로, 그 전까지 모델은 평소처럼 "예약 도와드릴게요"라고 말한다
  - 2번째 턴에서 추천 도구가 not_available을 줬는데도, 모델은 이를 "추천만 안 된다"로 이해하고 예약은 된다고 말했다

## 적용한 것 (2026-11-26)
프론트에서 국내 거주 계정은 예약·상담·찜을 막을 예정이다 (팀 결정). 챗봇도 같은 기준으로 맞췄다.

| 파일 | 바꾼 것 |
|---|---|
| `ai/agent/prompts/orchestrator.py` | 계정이 resident면 `RESIDENT_RULES`를 붙인다: 예약·요청·추천·찜을 먼저 권하지 않음 / 예약·추천을 요청받으면 도구를 부르지 않고 **그 턴에서 바로** "단기 방문자만 가능, 병원에 직접 연락" + 전화번호 / 병원 찾기·진료시간·가격 안내는 평소대로 |
| `ai/agent/tools/chat_tools.py` | resident면 `search_hospitals` 결과 note에 "상담 요청 불가, 예약 제안 말 것"을 붙인다. 목록 결과에 전화번호(`tel`)를 넣는다 (번호를 알려 주려고 병원마다 상세를 다시 부르던 문제) |
| `backend/src/modules/chatbot/hospitals.py` | DB 목록 결과에도 `tel` (한 줄) |
| `ai/agent/service.py` | **"첫 번째 병원"이 엉뚱한 병원을 가리키던 버그 수정**: 목록 속 병원의 상세를 보면 "보여 준 병원 목록"이 그 병원 하나로 바뀌어, "첫 번째 병원" = 마지막에 상세를 본 병원(B)이 됐다. 이제 목록 속 병원의 상세만 봤으면 목록 순서를 그대로 둔다 (국내 거주자만이 아니라 모든 대화에 해당) |
| `ai/agent/eval/run_resident.py` | 국내 거주 계정 평가 (새로 만듦) |
| 테스트 | `test_orchestrator`·`test_chat_tools`·`test_service`에 5개 추가. AI 230개 · 백엔드 297개 통과 |

서버 쪽 막기(`prepare_booking_request`·`recommend_hospitals`의 not_available)는 그대로 둔다. 프롬프트가 실수해도 초안이 만들어지지 않는다.

## 평가 결과 (nemotron, 3턴 × 3번)
| 확인 항목 | 1 | 2 | 3 |
|---|---|---|---|
| 1. 병원 찾기 턴: 목록 O, 예약·요청·찜 제안 없음 | O | O* | O |
| 2. 추천·예약 요청 턴에서 **바로** 안내 | O | O | O |
| 3. 2턴에서 추천·요청서 도구를 쓰지 않음 | O | O | O |
| 4. 예약 턴: 직접 연락 + 전화번호 | O | O | O |
| 4-1. "첫 번째 병원" = 1턴 목록의 첫 병원(A) | O | O | O |
| 5. 요청서 초안 카드 없음 | O | O | O |

- \* 2번 실행의 1번 항목은 평가 정규식 오탐이었다. 챗봇 답이 "상담 요청이나 추천은 해드릴 수 없습니다"였는데, 이 거절 문장이 제안으로 잡혔다. 정규식을 고쳤다. 다만 같은 답에 "(**저는** 한국 거주자이므로…)"처럼 주어가 틀린 문장이 한 번 나왔다 (사용자 → 챗봇)
- 고치기 전에는 3번째 턴에야 안내했다 → 이제 2번째 턴(추천·예약을 처음 말한 턴)에서 안내한다. 1번째 턴에 예약을 권하는 말도 없어졌다
- **회귀 확인**: 기존 단기 방문 시나리오(`run_scenario`) 12/12
- 시간: 턴당 2~24초, 한 번은 80초. 프롬프트가 아니라 NVIDIA 쪽 지연으로 보인다 (응답속도 점검 문서 6절 1번 "타임아웃·재시도 줄이기"가 여전히 필요)
