# 병원 대시보드: 예시 숫자가 먼저 보였다가 사라지는 문제 확인 (2026-11-26)

## 재현 (로컬, `backend-chatbot` 브랜치로 켠 서버, 직원 로그인 상태)
`/dashboard` 새로고침 뒤 "오늘 할 일" 칸을 시간별로 읽음

| 새로고침 뒤 | 새 상담 요청 | 오늘 방문 예정 |
|---|---|---|
| 0.3초 ~ 1.5초 | **5** (예시) | **2** · 11:00 · 15:30 (예시) |
| 3초 | **0** (DB 실제 값) | **0** |

- 원인: 옛 대시보드(`src/dashboard/demo/markup.html` + `legacy.js`)는 화면에 **예시 숫자를 먼저 그려 두고**, API(`/tenant/analytics/summary`, `/tenant/booking-requests`, `/tenant/aftercare` …) 응답이 오면 덮어쓴다. 응답이 오기 전 1~3초 동안 예시 숫자가 보인다
- 화면 날짜도 "11월 16일 (월)" 고정 → 어제 고친 코드가 이 서버에 없다는 뜻
- 반복 호출(폴링)은 없음: 처음 열 때 13번, 그 뒤 10초 동안 0번. 같은 요청이 두 번씩 보이는 것은 개발 모드(React StrictMode) 때문으로 보임 (미확인)

## 왜 "어제 고쳤는데" 그대로인가
지금 켜 둔 서버는 `backend-chatbot` 브랜치다. 이 브랜치는 `origin/backend`에서 시작해서 프론트 고친 것들이 **들어 있지 않다**.

| 고친 것 | 어디 있나 | main에 있나 |
|---|---|---|
| 어제(11/25) `91e9c0a` 오늘 날짜·기간 선택 + 로그인 뒤 예시 카드 흐리게·"예시" 표시 | `frontend-dashboard-dates` (PR #114, 열림) | 아니오 |
| 오늘(11/26) 새 대시보드 홈: "오늘 할 일"을 **불러오는 동안 "…"**, 실패하면 "—", 받은 뒤 실제 값 (`TodayTiles.tsx`) | `origin/frontend-dashboard-redesign` (PR 없음) | 아니오 |

- **깜빡임을 실제로 없애는 건 오늘 브랜치(`frontend-dashboard-redesign`)** 다. 어제 PR #114는 예시 카드를 흐리게 표시할 뿐, API가 오기 전에 예시 숫자를 먼저 그리는 구조는 그대로다
- 새 구조에서도 옛 화면은 `/dashboard/legacy`에 남아 있어, 그 주소로 들어가면 같은 깜빡임이 있다
