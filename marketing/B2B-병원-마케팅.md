# B2B 전략 — 병원을 직접 찾아가 계약까지

> 작성 2026-11-20 · **v2 다시 씀 2026-11-23: 직접 방문 중심, SEO 제외** · 상태: Claude 초안 + 팀 결정 반영, 팀 논의 전
> 결정 (2026-11-20 팀): **SEO 시스템은 현실적으로 어려워 하지 않고, 병원은 직접 찾아가서 만나요**
> 현장 실행(전화 대본·질문 7개·반론 답·기록 규칙)은 [병원-방문영업-플레이북.md](병원-방문영업-플레이북.md), 대상 목록은 [방문영업/대상병원_우선순위.csv](방문영업/대상병원_우선순위.csv)

## 0. 결론

**병원 161곳을 우선순위대로 직접 찾아가서 "팔기 전에 듣고", 들은 것으로 파일럿 → 유료 계약까지 가요.** 검색(SEO)·광고로 병원이 찾아오길 기다리지 않아요.

| 시기 | 목표 | 대상 |
|---|---|---|
| **발표 전 (~12/3)** | 병원 인터뷰 **3~5곳** — 문의 실태·대시보드 쓸모·가격(수수료/구독료) 반응 확인 | 1차 **중구 의원급 피부·성형 20곳** |
| **발표 뒤 1~2달** | 무료 사용 의향 병원 → **파일럿 3곳** (3개월 무료) | 1차에서 관심 보인 곳 + 2차 42곳 |
| **그 뒤** | 파일럿 결과(요청 수·응답 시간)를 사례로 → **유료 전환** · 3차·소개로 넓히기 | 3차 19곳 · 파일럿 병원 소개 |

## 1. 왜 직접 방문인가 (SEO를 하지 않는 이유)

| 근거 | 내용 | 출처 |
|---|---|---|
| **고객이 이미 정해진 좁은 시장** | 계약 대상 = 대구 등록 외국인환자 유치의료기관 **161곳**. 이름·주소·전화가 공공데이터로 다 있음 → 찾아오길 기다릴 이유가 없음 | [S3] |
| **두 구에 몰려 있음** | 중구 60곳 · 수성구 54곳 = **약 70%** → 걸어서 도는 동선이 나옴 | [S3] |
| **결정하는 사람이 가까움** | 1순위가 의원급이라 원장이 직접 결정 → 한 번 만나면 바로 답을 들을 수 있음 `[추정]` | 플레이북 2절 |
| **가격이 아직 가정값** | 기본 회원 무료 + 13% / 프리미엄 연 ₩1,800,000 + 8%는 "병원 인터뷰로 지불 의향 확인 후 확정" → **얼굴 보고 묻는 게 가장 빠른 검증** | [S2] |
| **SEO는 지금 할 수 없음** | 웹 주소(도메인) 미정 · 유치업자 등록 전에는 웹 공개 운영을 하지 않음 · 구글 반영에 보통 몇 주 · 병원이 "외국인 환자 유치 플랫폼"을 검색하는지도 미확인 → 자세히 **1-1절** | [S12] · [SEO-쉽게-설명.md](SEO-쉽게-설명.md) (보류) |

> 참고 틀: 엘리펀트컴퍼니 「B2B 기업 단계별 마케팅 전략」 [S1]은 1단계(초기)에 SEO·콘텐츠를 권하지만, 핵심 주장은 "유행 채널이 아니라 **지금 단계에 맞는 것부터**"예요. 메디대구는 계약 병원 0곳 · 가격 미검증인 **1단계 직전**이라, 틀의 "ICP·메시지 정의"와 "고객 사례 만들기"만 가져오고 SEO는 뺐어요

## 1-1. SEO를 해 보려다 부딪힌 한계 (2026-11-20 검토 → 보류)

처음에는 "병원 페이지를 검색에 잘 나오게 만들고(SEO) → 외국인이 본 숫자를 들고 병원을 설득하자"는 계획이었어요 ([SEO-병원영업-연결.md](SEO-병원영업-연결.md)). 실제 웹 코드와 일정·규제를 확인해 보니 아래 벽에 부딪혀 접었어요.

| 구분 | 부딪힌 한계 | 확인한 내용 | 근거 |

| **① 기술** | 지금 웹은 검색엔진이 거의 못 읽는 구조 | 화면을 브라우저에서 JavaScript로 그려서 첫 HTML은 빈 `<div id="root">`뿐 · 언어별 주소가 없어(`/hospitals/123` 하나) 번체·베트남어 페이지가 검색에 따로 안 잡힘 · 모든 페이지 제목이 `MediDaegu` 하나 · 사이트맵·robots.txt 없음 | [SEO-구축-계획.md](SEO-구축-계획.md) 1절 (frontend 코드 확인) |

### 한계별 상세 — 왜 안 되나

#### ① 기술: 지금 웹은 검색엔진이 내용을 못 읽어요
- **SEO에 필요한 것**: 검색엔진이 페이지를 열었을 때 병원 이름·진료시간 같은 **글자가 바로 보여야** 함
- **지금 상태**: 메디대구 웹(React + Vite)은 처음 받는 HTML에 빈 `<div id="root">`만 있고, 내용은 브라우저가 JavaScript를 실행한 뒤에야 그려져요 → JavaScript를 실행하지 않거나 늦게 실행하는 검색엔진·링크 미리보기는 **빈 페이지**로 봐요
- 언어도 브라우저 설정·저장값으로 바뀌고 주소는 하나(`/hospitals/123`)라서, 구글에는 **한 언어 페이지만** 보여요 → 대만 사람이 번체로 검색해도 번체 페이지가 안 나옴 (구글은 언어마다 다른 주소를 권장)
- 모든 페이지 제목이 `MediDaegu` 하나 → 검색 결과에서 어느 병원 페이지인지 구분 불가 · 사이트맵·robots.txt 없음
- **왜 막히나**: 이건 설정 몇 줄이 아니라 **화면을 만드는 방식 자체**를 바꿔야 하는 문제예요

#### ② 작업량: 프론트 한 명이 감당하기 어려운 규모
- **해야 할 일**: 언어별 주소(`/en/`, `/zh-tw/`, `/zh-cn/`, `/vi/`, `/ja/`, `/ko/`) + 서로를 알려 주는 hreflang 표시, 병원 161곳 × 6개 언어 ≈ **966개 페이지를 미리 HTML로 만들기**, 페이지별 제목·설명, 사이트맵, 로그인 화면 숨기기
- 가장 가벼운 방법(빌드 뒤 헤드리스 브라우저로 페이지 저장)도 **언어 전환·링크 구조를 전부 손봐야** 하고, 더 확실한 방법(Next.js 등으로 옮기기)은 사실상 다시 만드는 수준
- **왜 막히나**: 프론트는 지금 일본어 화면(PR #52)·예약·사후관리 화면을 마무리해야 해요. 발표(12/4)까지 남은 시간에 SEO 구조 변경을 넣으면 **발표용 기능이 밀려요**

#### ③ 일정: 해도 발표 전에는 결과가 없어요
- 구글이 새 페이지를 발견·색인하는 데 **보통 몇 주**가 걸리고, 노출·클릭 숫자가 의미 있게 쌓이려면 더 걸려요
- 원래 계획의 핵심은 "외국인이 원장님 병원 페이지를 **n번 봤어요**"라는 숫자로 설득하는 것이었는데, **발표 전에는 이 숫자가 0**이에요
- 지금 B2B에서 급한 건 숫자보다 **"병원이 수수료·구독료를 낼 의향이 있나"** 확인 → 이건 검색이 아니라 **대화로만** 알 수 있어요

#### ④ 주소·배포: 올릴 주소가 없어요
- 구글 서치 콘솔 등록·사이트맵 제출·검색 성적 보기는 모두 **확정된 웹 주소(도메인)** 가 있어야 시작돼요
- 메디대구는 도메인이 **미정**이고, 정식 배포 일정도 없어요 (지금은 로컬·시연용)
- 임시 주소로 먼저 쌓아도, 나중에 주소를 바꾸면 쌓인 검색 순위를 옮기는 작업이 또 필요해요

#### ⑤ 규제·운영: 웹을 공개하면 안 되는 단계예요 (가장 큰 벽)
- 복지부·진흥원 회신(2026-11-17): **외국어 병원 정보 웹도 유치 거래와 결부되면 "외국인환자 유치행위"로 볼 수 있고, 돈을 받지 않아도 마찬가지** → 유치행위는 **등록 유치업자만** 할 수 있어요 (무등록 유치는 3년 이하 징역 또는 3천만 원 이하 벌금, 해외진출법 제28조)
- 그래서 팀 기준은 "**유치업자 등록 전에는 일반 외국인 대상 공개 운영 X**, 시연만" (`docs/compliance.md` v2.3) → SEO는 **공개 페이지를 검색에 올리는 일**이라 이 기준과 정면으로 부딪혀요
- 공개하더라도 병원 목록·상세는 **등록 유치의료기관만** 보여야 하고(결정 21), 해외 대상 외국어 페이지가 국내에서 보이는 것이 "외국인환자 유치 **국내광고**"(의료법 제56조 제2항 제12호)에 걸리는지도 **복지부 해석이 없어요** ([마케팅-최신본.md](마케팅-최신본.md) 8장)
- **왜 막히나**: 등록·해석은 우리가 일정을 정할 수 없는 조건이에요

#### ⑥ 병원 쪽 효과: B2B 고객은 검색으로 오지 않을 가능성이 커요
- B2B SEO는 고객이 "문제 해결 방법"을 **검색할 때** 우리가 보이게 하는 것인데, 원장·상담 실장이 "외국인 환자 유치 플랫폼"·"외국인 예약 대시보드"를 검색해서 업체를 고르는지 **확인된 근거가 없어요** (검색량 미확인)
- 대상이 **161곳으로 정해져 있고** 이름·전화·주소를 이미 알아요 → 검색으로 찾아오길 기다리는 것보다 **먼저 연락하는 게** 빠르고 확실
- 병원 대상 글(블로그·사례)을 써도 읽을 사람이 161곳 안팎이라, 검색 유입으로 얻을 수 있는 병원 수가 처음부터 작아요

#### ⑦ 숫자 연결 기능: 보여 주려면 개발이 줄줄이 필요해요
- "검색 숫자를 들고 병원 설득"을 하려면 SEO 말고도 다음이 다 있어야 해요
  - 병원 페이지의 **"정보 확인·수정하기" 버튼 + 병원 무료 계정** (프론트 + 백엔드 병원 계정 작업)
  - 병원별 **상담 버튼 클릭 기록** (웹 분석 도구 — 미정, 쿠키 동의 여부도 미확인)
  - 공공데이터로 병원 정보를 보여 주는 **법적 조건 확인** (팀 노트상 "조건부 가능", 팀원 2)
- **왜 막히나**: SEO 하나가 아니라 **SEO + 계정 + 분석 + 법 검토**가 모두 끝나야 첫 숫자가 나와요

### 다른 방법으로 돌아갈 수는 없었나

| 웹은 비공개로 두고 병원 소개 페이지만 공개 | 병원 쪽 검색 수요 자체가 미확인(⑥) → 페이지가 있어도 찾아올 사람이 적음. 소개는 방문 때 1장 자료로 충분 |
| 등록된 유치업체와 제휴해 그 회사 이름으로 공개 | 제휴 상대·조건 미정 (CLAUDE.md "직접 등록 / 제휴 둘 다 검토") → 발표 전 실행 불가 |

**그래서**: SEO가 병원 영업에 숫자를 보태 주려면 ①~⑦이 **모두** 풀려야 하는데, 그중 ④⑤는 우리가 정할 수 없는 조건(도메인·유치업자 등록)이에요. 반면 직접 방문은 **오늘 바로** 시작할 수 있고, 지금 가장 필요한 가격·기능 검증을 바로 해 줘요.

**다시 검토할 조건** (모두 충족되면)
1. 유치업자 등록 완료 → 웹 공개 운영 가능
2. 도메인 확정 · 배포
3. 프론트에 언어별 주소·미리 그리기를 넣을 여유
4. 파일럿 병원이 생겨 "병원 페이지를 본 외국인 수"를 보여 줄 대상이 있음

> 환자 쪽(B2C) SEO도 같은 이유(①~⑤)로 함께 보류예요. 그동안 환자 유입은 SNS([마케팅-유입방법-고안.md](마케팅-유입방법-고안.md))로 해요

## 2. 전체 흐름 — 병원 한 곳이 계약까지 가는 단계

```
목록 → 전화 → 방문·인터뷰 → 데모 → 무료 사용 의향 ─(출시·등록 뒤)→ 파일럿 3개월 → 유료 계약
 161     20        5           5          2                         3곳             ?
```

| 단계 | 하는 일 | 다음으로 넘어가는 조건 | 1차 목표 (가정) |
|---|---|---|---|
| ① 목록 | 우선순위 점수로 차수 나누기 (4절) | 1차 20곳 확정 | 20곳 |
| ② 전화 | 오후 3~5시 전화, 15분 방문 약속 (플레이북 4-1) | 약속 잡힘 / 거절 시 자료 발송 | 약속 8곳 |
| ③ 방문·인터뷰 | **질문 7개로 듣기** (플레이북 5절) | 인터뷰 기록 | 만남 5곳 (최소 3) |
| ④ 데모 | 병원 대시보드 3분 시연 (가상 데이터) | 기능 반응 기록 | 5곳 |
| ⑤ 무료 사용 의향 | "출시하면 먼저 써 보실래요?" — **서명 없이 의향만** | 의향 있음 | 2곳 |
| ⑥ 파일럿 | 출시·유치업자 등록 뒤, 3개월 무료 사용 · 매주 요청 수·응답 시간 기록 | 3개월 사용 | 3곳 |
| ⑦ 유료 계약 | 파일럿 숫자를 보여 주고 요금제 제안 | 계약 | 파일럿 중 몇 곳 |

- 전환율(전화 → 약속 → 만남)은 1차 결과로 처음 알게 되는 값이에요. 2차부터는 그 숫자로 다시 계획해요

## 5. 무슨 말을 할까 — 메시지

**한 줄**: "외국인 환자 문의를 한 화면에서 받고 답하세요"

| 병원이 얻는 것 | 근거 (환자 쪽 문제) |
|---|---|
| **외국어 문의를 정리된 요청서로** — 언어·희망 날짜·관심 진료가 미리 정리돼 옴 | 환자 VOC: 예약 방법·채널을 몰라 헤맴 (10건) [S6] |
| **응답 상태 관리** — 확정 / 다른 시간 제안 / 불가로 답하고, 못 답한 문의가 쌓이지 않음 | 환자 VOC: "여러 채널로 연락했는데 일주일째 답이 없다" [S6] |
| **사후관리 대화** — 방문 완료한 환자와 귀국 뒤에도 대화 | 서비스 핵심 기능 [S2] |
| **광고·순위 없음** — 돈을 더 내도 목록 순서가 안 바뀜 | 병원 목록 정렬은 거리·이름만 [S7] |

**가격을 말하는 법**
- 트립닥은 병원 입점비·월 이용료·유치 수수료가 없다고 알리고 있어요 [S8] → "왜 돈을 내나"에 답이 필요
- 순서: **기본 회원은 월 0원**(결제 확인된 진료비의 13%만) → 환자가 월 3명을 넘으면 **프리미엄**(연 ₩1,800,000 = 월 환산 ₩150,000 + 8%)이 이득 → **법정 상한(의원 30%) 안** · 업계 공개 요율 15~25%보다 낮음 [S2][S9]
- 인터뷰(질문 6)에서는 **금액을 먼저 말하지 않고** 병원 생각부터 들어요

## 7. 방문을 더 효율적으로 — 보조 수단 (모두 방문을 돕는 용도)

| 방법 | 어떻게 | 언제 |
|---|---|---|
| **동선 묶기** | 같은 건물·같은 거리 병원을 한 번에. 약속 사이 근처 병원에는 자료만 두고 오기 | 1차부터 |
| **거절 → 자료 발송** | 방문을 거절하면 소개 1장 + 리포트를 메일·팩스로 → 1~2주 뒤 다시 전화 | 1차부터 |
| **리포트를 연락 이유로** | "대구 외국인 환자 통계 한 장 드리려고요"로 첫 통화 문턱 낮추기 | 1차부터 |
| **여러 병원이 모이는 곳 확인** | 대구시 의료관광 담당 부서·협의체, 진흥원 유치기관 설명회, 진료과 의사회 대구 지부 → 한 번에 여러 병원 소개 | **어떤 곳이 있는지 미확인** — 발표 전엔 확인만 |
| **파일럿 병원 소개** | 파일럿에 만족한 병원이 아는 병원 소개 | 파일럿 뒤 |
| 병원 정보 확인 초대 | 웹에 올라간 자기 병원 정보를 보여 주고 무료 병원 계정 초대 | **출시·등록 뒤** (등록 전 웹 공개 운영 X) |
