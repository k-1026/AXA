# 병원 대시보드 구성안 · 초기 화면(공공데이터)과 운영 후 화면

> 작성 2026-11-12 · 팀 기획(탭 4개: 홈·유입·관심·상담·예약·사후관리)에 공공데이터 초기 화면을 합친 것
> 관련: [병원-대시보드-초기데이터.md](병원-대시보드-초기데이터.md), [병원-대시보드-추가데이터.md](병원-대시보드-추가데이터.md), 구독 기준 `docs/subscription-plans.md` (통계 = 확장 플랜)
> 표기: **[판단]** = 작성자 판단 · **미확인** = 확인 못 함

## 한눈에

| 탭 | 병원의 질문 | 초기 화면 (데이터 없음) | 운영 후 화면 |
|---|---|---|---|
| 홈 | 이번 달 어느 단계가 좋아지고 떨어졌나? | 병원 정보 등록 상태 + **대구 시장 요약 (공공)** | 방문자·상담·확정·방문·취소율과 지난 기간 대비 |
| 유입·관심 | 어디에 홍보하고 어떤 언어·진료항목 설명을 보강할까? | 페이지 미리보기, 홍보 링크 만들기 + **대구에 오는·사는 외국인 (공공)** | 링크·언어·진료항목별 방문·상담·예약 |
| 상담·예약 | 어느 단계에서 환자를 놓치나? | 예약 시간·FAQ 등록 + **대구 같은 진료과 진료시간·가격 분포 (공공)** | 단계별 전환, 첫 답변 시간, 취소·변경 사유 |
| 사후관리 | 어떤 안내를 미리 하고 응대를 어떻게 고칠까? | 방문 후 안내문·체크리스트 등록 + **안내문 서식 (공공)** | 처리 현황, 반복 키워드, 주제별 추이, 개선 기록 |

- 초기 화면 = **병원이 채울 설정** + **공공데이터 카드**. 운영 데이터가 기준 이상 쌓이면 같은 자리에 운영 지표가 들어감
- 공공데이터 카드는 운영 후에도 "대구 기준선"으로 남김 (예: 우리 병원 언어 비중 vs 대구 외국인환자 국적 비중)

## 1. 홈

| 구분 | 내용 | 데이터 | 상태 |
|---|---|---|---|
| 초기 · 설정 | 병원 정보 등록 상태 (진료시간·홈페이지·통역 언어·상담 가능 시간·예약 가능 일정·가격 안내·사진) "n/7 완료" + 빠진 칸 바로 입력 | 심평원 진료시간·기본정보 API, 팀 수집 링크 | ✅ 보유 |
| 초기 · 설정 | 등록 유치의료기관 여부·등록번호 확인 (없으면 등록 안내) | KHIDI 등록기관 목록 (대구 161곳, 126곳 매칭) | ✅ 보유 |
| 초기 · 공공 | 대구 외국인환자 수·추이 (2009~2025, 2025년 19,243명) | KHIDI 통계 표 2.13·3.73 | ✅ 보유 |
| 초기 · 공공 | 대구 외국인 방문자 월별 추이 | 관광공사 지역별 방문자수 API (2024-01-01~2026-10-13, `data/raw/유입/daegu_visitors_daily.json`) | ✅ 보유 |
| 운영 후 | 상세페이지 방문자 → 상담 신청 → 예약 확정 → 방문 완료, 취소율, 지난 기간 대비 | 플랫폼 기록 | ⬜ |
| 운영 후 | 새 상담·예약 요청, 오늘 방문 예정, 미답변 문의 | 상담/예약·사후관리 페이지 | ⬜ (환자 쪽 화면은 있음) |

## 2. 유입·관심

| 구분 | 내용 | 데이터 | 상태 |
|---|---|---|---|
| 초기 · 설정 | 환자에게 보이는 병원 페이지 미리보기 (5개 언어 전환) | 환자용 사이트 `hospitals.json` | ✅ |
| 초기 · 설정 | 채널별 홍보 링크 만들기 (인스타·블로그·유치업체별 링크) → 이후 "유입 경로"의 기준이 됨 | 플랫폼 (링크 파라미터) | ⬜ |
| 초기 · 공공 | 대구에 오는 외국인환자 국적 순위·진료과별 | KHIDI 표 3.74·3.75 | ✅ |
| 초기 · 공공 | 국적별 전국 증가율 vs 대구 점유율 ("성장 여지") → 어느 언어 설명을 먼저 보강할지 | KHIDI 표 2.11·3.x | ✅ |
| 초기 · 공공 | 대구 사는 외국인 국적·구별 (베트남 13,321 · 중국 4,334 …, 2026-09) → 거주 외국인 대상 언어 | 법무부 등록외국인 (공공누리 4유형) | ✅ |
| 초기 · 공공 | 대구 구별 외국인 방문자 (우리 병원 있는 구 vs 대구) | 관광공사 API (2025년 외국인 방문 많은 구: 동구·달서구·중구) | ✅ 보유 |
| 초기 · 공공 | 외국인이 자주 찾는 병원의 주요 시술 (진료항목 설명 보강 참고) | KHIDI 주요진료시술 (대구 148행) | ✅ |
| 운영 후 | 경로별 방문자·상담·예약 (예: SNS 유입은 많은데 예약 적음 → 광고 내용과 병원 정보 일치 확인) | 홍보 링크 | ⬜ |
| 운영 후 | 언어별 상담·예약 비중 (예: 베트남어 문의 많은데 예약 적음 → 번역·응대 점검) | 상담 언어 | ⬜ |
| 운영 후 | 진료항목별 조회·상담 (조회 많은데 상담 적음 → 비용·절차 설명 보강) | 상세 조회, 상담 희망 진료 | ⬜ |
| 운영 후 | 상세페이지에서 누른 버튼 (전화·홈페이지·상담·길찾기·찜) | 클릭 기록 | ⬜ |

## 3. 상담·예약

| 구분 | 내용 | 데이터 | 상태 |
|---|---|---|---|
| 초기 · 설정 | 예약 가능 시간 설정, 자주 묻는 질문·답변 등록 | 병원 입력 | ⬜ |
| 초기 · 설정 | FAQ 기본 틀: 통역·결제·위치·예상 진료비 서면 안내 (유치기관 안내 의무, 해외진출법 제8조) | KHIDI 다국어 서식집, 법령 | ✅ 자료 보유 |
| 초기 · 공공 | 대구 같은 진료과 중 야간·토요일·일요일 진료 비율 vs 우리 병원 | 심평원 진료시간 API (내과·안과는 진료과목 코드 목록 확보) | ✅ |
| 초기 · 공공 | 비급여 가격의 대구 분포(최소·중앙·최대)와 우리 병원 위치 → 비용 설명 근거 | 심평원 비급여 (병원급 위주, 의원급 대부분 없음) | △ |
| 운영 후 | 병원 상세 조회 → 상담 시작 → 예약 신청 → 예약 확정 → 방문 완료 (어느 단계에서 놓치나) | 플랫폼 기록 | ⬜ |
| 운영 후 | 첫 답변 소요 시간 (운영시간 기준) | 상담 메시지 시각 + 병원 운영시간 | ⬜ |
| 운영 후 | 예약 취소·변경 사유 (일정·비용·통역·교통·다른 병원·기타/미응답), 반복 변경 건수 | 취소·변경 시 사유 선택 | ⬜ (환자 화면에 사유 선택 추가 필요) |
| 운영 후 | 희망 요일·시간대와 확정률 | 예약 요청 | ⬜ |

## 4. 사후관리

| 구분 | 내용 | 데이터 | 상태 |
|---|---|---|---|
| 초기 · 설정 | 방문 후 안내문·체크리스트 작성 (언어별) | 병원 입력 | ⬜ |
| 초기 · 공공 | 안내문 서식 예시 (귀국 후 주의사항·연락처·분쟁 상담 메디컬코리아) | KHIDI 다국어 서식집, 메디컬코리아 | ✅ 자료 보유 |
| 초기 · 공공 | 통계로 쓸 공공데이터는 **거의 없음** → 초기 화면은 설정 중심 | — | — |
| 운영 후 | 처리 현황: 신규·미답변·처리 중·해결 완료 | 사후관리 대화 | ⬜ |
| 운영 후 | 반복 키워드 (안내 부족·통역·대기시간·비용 설명·재방문 일정), 주제별 추이 (지난달 대비) | 대화 분류 (AI) | ⬜ |
| 운영 후 | 대표 사례: 개인정보 가린 짧은 요약 + 원래 대화 열기 | 대화 요약 | ⬜ |
| 운영 후 | 개선 기록: 병원이 고친 안내와 고친 뒤 문의 변화 | 안내문 수정 이력 | ⬜ |
| 운영 후 | 만족도 | 방문 완료 후 설문 | ⬜ (비공개 · 병원 내부용만) |

## 공통 원칙

| 원칙 | 내용 |
|---|---|
| 실제 vs 예시 | 공공 숫자는 출처·기준 시점 표시, 프로토타입의 가짜 운영 숫자는 "예시" 배지 |
| 표본이 적을 때 | 국적·언어 칸 5명 미만 숨김, 조회 월 30회 미만은 "집계 중" **[판단]** |
| 개인정보 | 사후관리·상담 내용은 건강정보 → 병원 내부에서만, 대표 사례는 이름·연락처·사진 가림 |
| 비교 | 다른 특정 병원과 1:1 비교 X, 대구 전체 분포만 |
| 의료광고 | 만족도·후기는 환자용 화면에 공개하지 않음 (치료경험담 유형, `웹사이트-법적-점검.md`) |
| 요금 | 통계는 구독 확장 플랜 기능, 예약 건수와 연동하지 않음 (`docs/subscription-plans.md`) |

## 환자 화면에 먼저 필요한 것 (운영 데이터 수집용)

- 홍보 링크 파라미터 기록 (유입 경로)
- 상세페이지 버튼 클릭 기록
- 예약 취소·변경 시 사유 선택
- 방문 완료 후 만족도 (선택)
