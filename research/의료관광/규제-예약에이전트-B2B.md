# 규제 Q4. 병원에 "예약 에이전트"를 제공하면 유치사업자가 아닌가?

> 작성 2026-10-29 · 근거: 법령 원문 [1][2], 판례 [3][4] · 법적 판단이 아니라 조문·판례에 비춘 정리. **이 구조를 직접 다룬 판례·해석은 못 찾음**
> 결론 등급: **병원 쪽 도구로 설계하면 가능성 있음 / 환자 쪽 대리·건당 수수료면 유치(등록 필요)**

## 한 줄 결론

핵심은 **에이전트가 누구 편에서 일하느냐**와 **돈을 어떻게 받느냐**다.
- 에이전트가 **병원의 접수 창구 역할**(병원 이름으로 응대, 병원이 계약 주체)이고 우리는 **소프트웨어 이용료(고정)**만 받으면 → 예약은 병원 자신의 행위, 우리는 도구 공급자에 가까움
- 에이전트가 **환자 대신** 병원을 고르고 예약하거나, 우리가 **예약·환자 1명당 돈**을 받으면 → "진료예약 대리" + 알선 대가 = 유치

## 1. 법이 보는 지점

| 조문·판례 | 내용 | 예약 에이전트에 적용 |
|---|---|---|
| 해외진출법 제2조 제3호 [2] | 유치 = 진료예약·계약 체결 **및 그 대리**, 진료정보 제공 등 편의 제공 | 환자를 **대리**해 예약하면 유치. 병원이 **자기 예약**을 받는 건 병원의 행위 |
| 해외진출법 제6조 제1항 [2] | 외국인환자를 유치하려는 **의료기관도 등록** | 에이전트를 쓰는 병원은 **등록 유치의료기관**이어야 함 |
| 대법원 2018도20928 [3] | 알선 = 환자와 특정 의료기관 사이 **치료위임계약 성립을 중개하거나 편의를 도모** | 우리 정보 사이트에서 **특정 병원 예약으로 바로 이어지면** 중개로 볼 여지 |
| 대법원 2021도10046 [4] | 영리 목적 = 의료기관 측 이익을 **나눠 받는 것** 전제 | **건당·성과 수수료**는 이익 분배에 가까움. 환자 수와 무관한 고정 이용료는 상대적으로 멀어짐 (판례 직접 판단 아님) |
| 의료법 제27조 제1항 [1] | 비의료인 의료행위 금지 | 에이전트는 날짜·서류·절차만. 증상 판단·시술 추천 X |
| 의료법 제34조의9 제1항 제4·5호 [1] | (비대면진료 중개업자에게) 소개·알선 대가 수수, 특정 병원 유도 금지 | 직접 적용은 아니지만 **설계 기준**으로 참고 |

## 2. 구조별 판단

| 구조 | 판단 | 이유 |
|---|---|---|
| A. 병원이 자기 홈페이지·채널에 우리 에이전트를 붙여 씀 (월 고정 이용료) | **가능성 높음** | 예약 주체 = 병원. 우리 = 예약 시스템 업체 |
| B. 우리 정보 사이트에서 병원 상세 → "예약하기" → 그 병원의 에이전트로 연결 (고정 이용료) | **회색지대** | 정보 노출과 예약이 한 화면에서 이어짐 → 이용 병원만 "예약 가능"이면 **유료 병원 우대** = 광고·알선 성격 |
| C. 예약 1건당·환자 1명당 수수료 | **유치(등록 필요)** | 알선 대가 [3][4], 수수료율 상한 적용 대상(제9조) |
| D. 에이전트가 환자 요청을 받아 **여러 병원 중 골라** 예약 | **유치(등록 필요)** | 환자 쪽 "진료예약 대리" [2], 특정 병원 선택 = 알선 [3] |

## 3. A·B로 갈 때 지킬 조건

1. **계약 상대는 병원**, 에이전트는 **"○○병원 예약 도우미"**로 병원 이름으로 응대 (우리 브랜드로 환자를 받지 않음)
2. **고정 이용료** (예약 건수·환자 수·진료비와 연동 X)
3. **등록 유치의료기관만** 이용 가능
4. 정보 사이트(공공정보)와 예약 도구는 **분리**: 목록·정렬·필터는 이용 여부와 무관하게 동일. "예약 가능" 표시로 순서를 바꾸지 않음
5. 에이전트 범위: 예약 날짜, 필요 서류, 비자용 예약확인서 요청 안내까지. **진단·시술 추천·가격 흥정 X**
6. 환자 개인정보는 **병원이 처리 주체**, 우리는 위탁받아 처리 (개인정보보호법 위탁 조항 원문 **미확인**)

## 4. 남은 의문 (기관 질의 권장)

- 고정 이용료형 예약 SaaS가 해외진출법상 "유치 편의 제공"에 해당하는지 → **보건복지부 / 한국보건산업진흥원 질의**
- B 구조(정보 사이트 → 병원 에이전트 연결)를 알선으로 볼지 → 판례 **미확인**
- 발표에서는 **A(병원용 도구)**를 "확장 수익 모델"로, 정보 서비스(공공 위탁)를 본체로 두는 것이 안전
