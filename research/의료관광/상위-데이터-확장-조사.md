# 의료관광 · 상위 데이터 확장 조사 (방향: 대구 의료관광객 늘리기)

## 1. 한 줄 요약
주제 선정 때 쓴 데이터(대구 환자 수·비급여 API)보다 한 단계 위의 데이터 — **국적별 환자 통계, 공항 노선, 카드 기반 의료관광 소비, 메디컬코리아 병원 원천 데이터** — 를 붙이면 "어느 나라 환자를, 어떤 시술·동선으로, 어느 병원에 연결할지"까지 설계할 수 있음.

### 메디컬코리아 CSV 실제 분석 (2026-10-28 다운로드) [2][3][4][5]

- 인코딩 CP949 → UTF-8 변환 필요. 기본정보 63개 열, 14,403행 (사이트언어는 전부 EN)
- 대구 행(지역 DAEGU/Daegu): **537행**. 단, 성격이 섞여 있음 ('콘텐츠타입' 열 기준)

| 콘텐츠타입 | 대구 행 수 | 사용여부 |
|---|---|---|
| 외국인 자주 찾는 병원 (MOST_VISITED) | 13 (사용 10) | Y 10 / N 3 |
| 등록 병원 (REGISTERD_HOSPITALS) | 145 | 모두 Y |
| 등록 유치업체 (REGISTERD_FACILITATORS) | 54 | 모두 Y |
| 백업 행 (…_BACKUP) | 325 | 모두 N |

- 대구 등록 병원 145곳의 구별 분포(주소 기준): 중구 50 · 수성구 47 · 달서구 24 · 동구 11 · 북구 4 · 남구 4 · 달성 3 · 서구 2
- **상세 정보는 13곳뿐**: 의사 수·병상 수·소개·일/중/러 병원명은 13곳(일부 11곳)만 채워짐. 나머지는 병원명·주소·전화 위주
- 주소는 537행 모두 있음(영문), **좌표·우편번호 없음** → 지도에 쓰려면 지오코딩 필요
- **진료시간·휴무일·시술 가격 열은 없음**
- 대구 13곳 연결 데이터: 의료인증 13건(KOIHA 8, JCI 1, 빈값 4), 전문과목 94건, 픽업 64건(사이트언어별 중복 포함, EN 기준 공항 출발 6건)
- 다국어 필드는 영·일·중(간체 추정)·러만 있음 — 2025년 대구 급증 국적인 **대만(번체)·태국·베트남어는 없음** [1]

## 4. 콘텐츠·서비스 관점에서 눈에 띄는 점 (의료관광객 늘리기)
1. **성장 국적과 신규 노선이 겹침** — 2025년 대구 환자는 중국(+173.8%)·대만(+500.4%)·일본(+128.8%)이 급증 [1]. 대구공항은 2026-09 이스타항공 장자제 노선(주 2회)을 시작했고 상하이 노선을 내년 추진 중 [8][9]. 다만 대구공항 외국인 입국객은 2026년 1~5월 46,146명으로 2019년 같은 기간의 58.3% 수준 [8]. → **노선 도시별 타깃 상품·다국어 우선순위** 설계 근거.
2. **대구 의료관광 소비는 전국과 반대로 감소** — 2026년 1~7월 전국 +60.1%, 대구 -8.9% (한국관광공사 자료 인용 보도) [7]. 동시에 대구공항 입국객의 대구 소비 1위는 의료관광(26.4%) [7]. → 수요는 있으나 성장에서 밀리는 상태, "왜 감소했나"가 핵심 질문.
3. **입국객이 대구에 머물지 않음** — 대구공항 입국객 중 다른 시도로 이동한 사람의 경북행 비중 50.1% [7]. 대구시는 체류형 메디웰니스 상품(약 10개 기관, 20개 이상 상품)을 공모 중 [10]. → "시술 + 회복 + 관광" 체류 동선을 병원 데이터(픽업·언어·인증)와 묶는 서비스.
4. (참고) **전국 트렌드는 피부과·약국** — 전국 외국인 의료소비 비중 피부과 55.72%, 약국 12.49%(2026년 1~9월, 카드 기반 추산) [11]. 대구에도 같은 흐름인지는 **미확인**.

### 심평원 병원정보 API (진료시간·휴진·좌표) [12][13]

API 명세(공공데이터포털 swagger)에서 응답 항목 확인 — 실제 호출·값 채움 비율은 **미확인**

| API · 기능 | 우리에게 필요한 항목 |
|---|---|
| 병원정보서비스 `getHospBasisList` (병원기본목록) [12] | 암호화 요양기호(ykiho), 병원명, 종별, 주소, 전화, 홈페이지, **XPos·YPos(좌표)**, 의사총수·전문의 수, 시도·시군구 코드 |
| 의료기관별상세정보서비스 `getDtlInfo2.8` (세부정보) [13] | **요일별 진료 시작·종료시간(월~일)**, 평일·토요일 점심시간, 평일·토요일 접수시간, **일요일·공휴일 휴진 안내**, 주차, 응급실 운영 여부 |
| 의료기관별상세정보서비스 `getDgsbjtInfo2.8` (진료과목) [13] | 진료과목명, 과목별 의사 수 |
| 의료기관별상세정보서비스 `getTrnsprtInfo2.8` (교통) [13] | 교통편, 노선번호, 하차지점, 거리 |

- 공통 키 **ykiho** → 비급여 API(가격)와 같은 키라 병원 단위로 바로 결합 가능
- 조건: 무료, 공공누리 1유형, 개발계정 일 10,000건, 갱신 "실시간"(요양기관 신고 기준) [12]
- 한계: 신고 기준 정보라 **임시 휴진·당일 변동은 없을 가능성** (추정). 좌표계(XPos·YPos가 WGS84인지) **미확인**
- 메디컬코리아 데이터에는 ykiho가 없음 → 병원명·주소로 매칭 필요 (매칭률 **미확인**)

### 팀 기능 아이디어 검토 (데이터 기준)

| 기능 | 판단 | 근거 / 보완 |
|---|---|---|
| 다국어 (i18n + 언어 자동 선택) | 방향 맞음 | 화면 문구는 i18n, 병원 정보는 미리 번역해 저장, 챗봇 답변은 LLM이 선택 언어로 생성. 브라우저 언어로 기본값을 정하고 수동 변경 허용. 지원 언어 우선순위는 대구 국적별 환자 수 기준 [1]: 영어·중국어(간체)·베트남어·중국어(번체)·태국어·일본어 |
| 저렴한 모델 사용 | 가능, 조건부 | 답을 모델 지식이 아니라 **API에서 가져온 데이터 안에서만** 하게 하면 작은 모델로도 충분할 가능성 (추정). 가격·시간 같은 숫자는 코드가 데이터에서 그대로 넣고 모델은 문장만 작성. 태국어·베트남어 품질은 언어별로 직접 테스트 필요 |
| 병원별 정보·시술 가격·휴무·진료시간 챗봇 | 대부분 공식 API로 해결 | 진료시간·점심·일요일/공휴일 휴진 → 심평원 `getDtlInfo2.8` [13]. 가격 → 비급여 API. 둘 다 ykiho로 연결. **크롤링은 임시 휴진·이벤트 가격 등 API에 없는 것만** (약관·robots 확인 필요) |

## 6. 확인이 더 필요한 항목 (근거 약함)
- 대구 환자 1위가 미국(31.7%)인 이유 — **미확인** (주한미군 등 거주 외국인일 가능성은 추정일 뿐, 근거 없음)
- 데이터랩 의료관광 소비의 **대구 시도별 수치** 제공 여부 — 미확인 (Claude in Chrome으로 대시보드 직접 확인 필요)
