# 폴더 구조 v2 검토 (apps 분리 + 병원 대시보드 + 에이전트)

> 작성 2026-10-29 · 대상: 팀 구조안 v2 (`apps/web-platform`, `apps/web-hospital`, `ai/llm`, `ai/agent` 등)
> 기준: [plan.md](../../subject/plan.md), 규제 노트 `research/의료관광/규제-*.md`
> 이전 검토: [폴더구조-무료LLM-검토.md](폴더구조-무료LLM-검토.md)

## 결론

- **방향 좋음**: 앱 2개 분리(= plan의 웹페이지 2개), `ai/llm` 공통 계층(LLM 교체·비용 추적), `tenant` 병원별 데이터 격리, `automation-log` 감사 기록은 규제 대응에도 유리
- **고칠 것 4가지**: ① 규제상 뺀 기능이 다시 들어옴(aftercare·discount) ② 시연 핵심인 **예약 요청·캘린더**가 빠짐 ③ 구독 요금 기준이 예약 건수면 수수료처럼 보임 ④ `shared-types`는 Python 백엔드와 공유 방식 필요

## 1. 그대로 좋은 것

| 항목 | 이유 |
|---|---|
| `apps/web-platform` + `apps/web-hospital` | plan.md 목표(환자용 정보 웹 / 병원용 대시보드)와 1:1 대응 |
| `ai/llm/` (client·config·usage_tracker·retry) | 무료 API 정책이 바뀌어도 `.env`만 바꿈. 병원별 사용량 기록 가능 |
| `ai/llm/safety.py` | 개인정보 마스킹 → 해외 LLM 국외 이전 부담 감소 (개인정보보호법 제28조의8) |
| `backend/modules/tenant/` | 병원별 데이터 격리 = 수탁자는 위탁 범위 밖 이용 금지(개인정보보호법 제26조 제5항)를 구조로 지킴 |
| `web-hospital/automation-log/` | 에이전트가 한 일 기록 → "직원 승인 후 발송" 증명, 질의 회신 대응 자료 |
| `docs/agent-spec.md` | 할 수 있는 일 / 하면 안 되는 일 문서화 (plan.md 4절 표를 옮기면 됨) |

## 2. 고칠 것

| # | 항목 | 문제 | 제안 |
|---|---|---|---|
| 1 | `backend/modules/aftercare/`, `ai/agent/tools/aftercare_followup.py` | 사후관리 Q&A는 **멘토 판단 "구현 불가"**. 시술 후 n일차 안내도 원격 "상담 및 교육"이면 비대면진료 정의에 들어감(의료법 제34조의2 제2항) | **삭제**. 남긴다면 이름을 `revisit_reminder.py`로 바꾸고 **재방문 일정·서류 안내 같은 행정 알림만** (의료 내용 X) |
| 2 | `backend/modules/discount/` | 이벤트 할인가·할인율 노출 = 의료광고 위험, 서비스 경계에서 "안 한다"로 정함 | **삭제** |
| 3 | `backend/modules/consultation/`, `tools/translate.py` "상담 번역" | 1:1 실시간 상담은 확장 단계 | MVP에선 `translate.py`를 **예약 요청서·답장 번역**용으로만. `consultation/`은 빈 폴더로 두지 않기 |
| 4 | **예약 요청·캘린더 없음** | 시연 핵심(요청서 → 병원 캘린더 "대기" → 확정)이 구조에 안 보임 | `backend/modules/booking/`(요청·상태값), `web-platform/features/booking-request/`, `web-hospital/features/calendar/` **추가** |
| 5 | `subscription/` "사용량 한도" | 요금이 **예약 건수·환자 수·진료비**에 따라 오르면 건당 수수료처럼 보임(대법원 2018도20928, 2021도10046 취지) | 플랜 기준 = **기능·좌석(직원 수)·AI 사용량**. 예약 확정 건수는 요금 기준에서 제외 → `docs/subscription-plans.md`에 명시 |
| 6 | `agent-settings/` "자동화 범위" | 자동 발송이 의료 내용까지 가면 의료 판단 개입 | 자동 발송 허용 = **접수 확인 메시지만**. 답장은 항상 직원 승인. 설정 화면에서 의료 내용 자동화는 켤 수 없게 |
| 7 | `analytics/` 문의 국적·시술 통계 | 병원 데이터를 플랫폼 전체 통계·다른 병원 홍보에 쓰면 위탁 범위 밖 이용 | **해당 병원 데이터만** 집계. 플랫폼 통계는 공공 통계(진흥원 보고서)만 |
| 8 | `packages/shared-types/` | 백엔드가 FastAPI(Python)라 TS 타입을 직접 못 씀 | FastAPI가 만드는 **OpenAPI 스키마 → TS 타입 자동 생성**(예: openapi-typescript)으로 `shared-types` 채우기 |
| 9 | `docs/compliance.md` 없음 | 서비스 경계 표가 개발 문서에 없음 | `docs/compliance.md` 추가 (plan.md 5절 표) |
| 10 | `data/` 표기 없음 | — | 기존 `data/raw·interim·processed` + `etl/`·`schemas/` 유지 |

## 3. 수정 반영 구조

```
apps/
├── web-platform/src/features/
│   ├── map/ hospital/ price-info/ chatbot/
│   └── booking-request/        # 예약 요청서 + 요청 상태
└── web-hospital/src/features/
    ├── calendar/               # 요청 "대기" 표시, 확정·거절·시간 제안
    ├── inbox/                  # 문의함 + AI 답장 초안 확인·승인
    ├── agent-settings/         # 말투·FAQ (의료 내용 자동 발송 불가)
    ├── automation-log/         # 에이전트 작업 기록
    ├── subscription/           # 플랜 (기능·좌석·AI 사용량 기준)
    └── analytics/              # 해당 병원 데이터만
backend/src/modules/
├── hospital/ price/ auth/
├── booking/                    # 요청·상태값(대기·확정·거절·제안)
├── tenant/ subscription/ agent/
ai/
├── llm/  client.py config.py usage_tracker.py safety.py retry.py
├── chatbot/  ingestion/ embeddings/ retriever/ prompts/ eval/
└── agent/
    ├── core/ workflows/ prompts/ memory/ eval/
    └── tools/  draft_reply.py translate.py summarize_request.py schedule.py
packages/shared-types/          # OpenAPI → TS 자동 생성
data/  raw/ interim/ processed/ etl/ schemas/
docs/  compliance.md agent-spec.md subscription-plans.md
```

- 뺀 것: `aftercare/`, `aftercare_followup.py`, `discount/`, `consultation/`(확장 단계에 추가)
- 이름 바꾼 것: `summarize_consult.py` → `summarize_request.py` (상담 내용이 아니라 **예약 요청서** 요약)
